Secure Development Lifecycle

A systematic process for building software that ensures security is addressed at every phase, rather than as an afterthought. It acts as a defensive framework to mitigate risks before a product reaches production.

The SDLC is comprised of specific stages designed to protect data and systems by blocking the path from Threat to Attack.

01

Planning & Requirements

Defining security goals and identifying sensitive data that requires protection.

02

Design

Creating the architecture and conducting Threat Modeling to anticipate how an attacker might strike.

03

Implementation (Coding)

Writing secure code and using tools like Static Analysis to find vulnerabilities early.

04

Verification (Testing)

Testing the application for weaknesses using automated and manual security reviews.

05

Release & Maintenance

Deploying securely and monitoring for new threats using tools like Microsoft Defender for Cloud.

// SDLC Defensive Logic: Mitigating Attacks

# Threat: SQL Injection / Data Tampering
# SDLC Defense: Implementation & Verification (Input Sanitization + Hashing)

import hashlib

def secure_store_data(user_input):
    # 1. Implementation Phase: Sanitize/Standardize
    clean_data = str(user_input).strip() 
    
    # 2. Integrity Phase: Generate Hash 
    data_hash = hashlib.sha256(clean_data.encode()).hexdigest()
    
    return {"data": clean_data, "integrity_token": data_hash}

# Verification: If the hash changes, we know an attack occurred
entry = secure_store_data("Sensitive Account Info")
print(f"SDLC Goal (Integrity): {entry['integrity_token']}")

Information Protection Model: The CIA Triad Model

Confidentiality

Encrypting and decrypting data using simple algorithms.

Integrity

Using hashes to verify data has not been altered.

Availability

Simulating service uptime checks to ensure resource access.

// CIA Triad Implementation

import hashlib
from cryptography.fernet import Fernet

# 1. CONFIDENTIALITY
key = Fernet.generate_key()
fernet = Fernet(key)
encrypted = fernet.encrypt("Secret message".encode())

# 2. INTEGRITY
def get_hash(data):
    return hashlib.sha256(data.encode()).hexdigest()

# 3. AVAILABILITY 
def ping_service(status):
    return "Online" if status else "Offline"

Procedures, standard and policy

POLICY Why do we need to do this?

Requirement: All company data must be encrypted to ensure confidentiality.

STANDARD What is required to achieve it?

Requirement: AES-256 is the mandated encryption algorithm for all mobile devices.

PROCEDURE How do we do what is required?

Steps: 1. Open BitLocker settings. 2. Select the C: Drive. 3. Generate a 256-bit recovery key.

TECHNICAL CONTROL How do we regulate necessary operations?

Enforcement: Active Directory script that denies system access if BitLocker is disabled.

*BitLocker is a full-disk encryption feature included with Microsoft Windows versions starting with Windows Vista. It is designed to protect data by providing encryption for entire volumes, ensuring that even if a device is lost or stolen, the information on the drive remains inaccessible to unauthorized users

Authentication

Authentication is the process of verifying the identity of a user or system. It ensures that the person or system requesting access is who they claim to be.

1. Credentials

  • Passwords: Most common form.
  • Biometrics: Fingerprints or facial recognition.
  • Tokens: OTPs, smart cards, or key fobs.

2. MFA

Uses two or more methods to verify identity:

  • • Something you know (Password)
  • • Something you have (Token)
  • • Something you are (Biometrics)

3. Protocols

Facilitates secure identity exchange:

OAuth SAML OpenID

// Simple MFA Logic Simulation

def authenticate_user(password, provided_otp, actual_otp):
    # Requirement: Two-Factor Authentication
    primary_auth = (password == "SecurePass123")
    secondary_auth = (provided_otp == actual_otp)
    
    if primary_auth and secondary_auth:
        return "✅ Authentication Successful: Identity Verified"
    elif primary_auth:
        return "⚠️ MFA Required: Please enter the correct OTP"
    else:
        return "❌ Authentication Failed: Invalid Credentials"

# Test MFA
print(authenticate_user("SecurePass123", "555666", "555666"))

Authorization

Authorization is the process of determining what resources and actions a verified user is permitted to access. It involves granting or denying permissions based on predefined rules or policies.

🔐

Components of Authorization

Authorization is the process of determining what resources and actions a verified user is permitted to access. It involves granting or denying permissions based on predefined rules.

🏗️ Access Control Models

  • RBAC: Access based on organizational roles.
  • ABAC: Decisions based on attributes like time or location.
  • DAC: Resource owner controls access.

📝 Permissions

Defines specific allowed actions:

READ WRITE DELETE

⚖️ Access Policies

  • Rules and conditions for granting access.
  • Often enforced via policy management tools.
  • Example: Access limited to 1 month.

// Authorization Logic Simulation

# Component Interaction: Model + Policy + Permission
def authorize_request(user_role, action, duration_days):
    # 1. Model (RBAC)
    permissions = {"Admin": ["read", "write", "delete"], "User": ["read"]}
    
    # 2. Permission Check
    if action not in permissions.get(user_role, []):
        return "❌ Denied: Insufficient Permissions"
        
    # 3. Access Policy Check (Example: Temporary Access)
    if duration_days > 30:
        return "❌ Denied: Policy limits access to 30 days"
        
    return f"✅ Authorized: {user_role} may {action}"

print(authorize_request("User", "read", 15))  # Success
print(authorize_request("Admin", "delete", 45)) # Policy Violation

Identity & Access Management (IAM)

RBAC (Role-Based)

Access is granted based on organizational roles.

  • Grant Least Privilege.
  • Avoid broad role scopes.
  • Max 3 subscription owners.

ABAC (Attribute-Based)

Decisions based on attributes like time or location.

  • Time-based (9 AM - 5 PM).
  • Location (Specific IP range).
  • Temporary (e.g., 1 month access).

// RBAC vs ABAC Logic

# --- RBAC Logic ---
def rbac_authorize(user_role):
    # Access based strictly on the 'Role' attribute
    if user_role == "Subscription Owner":
        return "✅ Access Granted"
    return "❌ Access Denied"

# --- ABAC Logic ---
def abac_authorize(user_role, current_hour, location):
    # Access based on Role + Time + Location
    if (user_role == "Admin" and 
        9 <= current_hour <= 17 and 
        location == "Internal_Network"):
        return "✅ Contextual Access Granted"
    return "❌ Access Denied: Policy conditions not met"

# Testing IAM Models
print(f"RBAC: {rbac_authorize('Reader')}")
print(f"ABAC: {abac_authorize('Admin', 22, 'Internal_Network')}") # Denied due to time
